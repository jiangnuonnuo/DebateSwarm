# 会议协作商业化迁移方案 V1（基于当前代码能力）

## 1. 当前能力盘点（已在代码中存在）

### 1.1 已可直接复用
- 房间体系：创建房间、成员管理、历史消息拉取、WebSocket 实时对话（`/chat-room/*`）。
- 多智能体房间对话：支持 `@` 指定成员响应、批量并发回复（`MultiMentionExecutionService`）。
- 辩论引擎：仲裁者设置、开始/裁决/下一轮/停止、状态查询（`/chat-room/debate/*`）。
- 会议治理后端：会议创建、开始、动作流转、状态与时间线（`/chat-room/meeting/*`）。
- 智能体工作台：Studio 创建、Repository 管理、Plaza 分发与互动。
- 运营后台：Dashboard、配置管理、会话审计。

### 1.2 当前主要缺口
- 会议治理 API 已有，但前端缺少“会议控制台”页面与流程 UI（现阶段 RoomChat 主要是辩论面板）。
- 尚未形成可收费产品闭环：无套餐、额度、账单、支付、团队成员席位控制。
- 缺少“结果交付价值”入口：标准会议纪要导出、任务同步、链接分享等仍偏弱。

## 2. 推荐商业化定位（建议聚焦）

### 2.1 产品定位
`AI 评审会议室`（面向小团队老板/产品经理/外包团队）

### 2.2 解决的高价值问题
- 需求评审反复扯皮、结论无法沉淀。
- 退回修改缺少可追踪链路。
- 会议结束后没有可执行行动项和责任归属。

### 2.3 为什么这个方向更容易赚钱
- 你当前代码里“房间 + 角色 + 状态机 + 时间线”几乎就是会议协作 SaaS 的核心骨架。
- 相比“泛 AI 聊天站”，会议协作对 B 端更有明确付费理由（省沟通成本、提决策效率、降低返工）。

## 3. 功能迁移策略（从现有能力改造，不重做）

### 3.1 保留并强化
- `RoomChat`：保留为统一协作入口（消息流 + 系统通知）。
- `MeetingController + MeetingGovernanceService`：作为核心收费功能引擎。
- `Studio/Repository/Plaza`：保留，但降级为增长辅助，不做首页主入口。

### 3.2 新增关键功能（用于变现）
- 会议控制台（前端）：创建会议、角色分配、动作按钮（通过/退回/指派/结论/终止）。
- 结构化产出页：结论、问题单、行动项、下一轮条件。
- 导出能力：Markdown/PDF 导出会议纪要（可先做 Markdown）。
- 团队空间：团队成员、会议权限、席位限制（Free/Pro）。
- 套餐与额度：每月会议数、每场最大角色数、历史保留天数。

### 3.3 暂缓项（避免早期分散）
- 复杂流程画布高级编排（保留管理端，不作为 MVP 主卖点）。
- Plaza 社区深运营（先保留基础，不投入过多产品资源）。
- 自动执行 DevOps 全链路（放到后续“高阶套餐”）。

## 4. MVP 收费版本（建议 4 周）

### 4.1 第 1 周：打通可演示闭环
- 在 `frontend/src/request/api.js` 增加 meeting API 封装。
- 在 `RoomChat.vue` 增加“会议模式”面板（与辩论模式并列）。
- 对接 `/chat-room/meeting/create/start/status/timeline/action`。

### 4.2 第 2 周：让结果可交付
- 会议结果页（结论 + 行动项 + 问题单）。
- 会议纪要导出 Markdown。
- 会议详情可分享只读链接（可先做登录内分享）。

### 4.3 第 3 周：接入基础商业化能力
- 套餐限制（免费版限制会议次数与历史条数）。
- 团队/席位管理（最小可用版）。
- 管理后台新增“套餐/用量”统计看板。

### 4.4 第 4 周：小流量验证与收款
- 接入支付（先选一个支付通道）。
- 上线落地页：强调“需求评审闭环 + 责任追踪”。
- 跑 10~20 个种子团队试用并追踪转化。

## 5. 收费设计（先简单，再迭代）

- Free：每月 5 场会议、每场最多 3 角色、历史保留 7 天。
- Pro（个人/小团队）：每月 99 元，50 场会议、每场 8 角色、导出与历史长期保留。
- Team：每月 299 元起，团队席位、共享模板、审计日志、优先支持。

## 6. 预期结果（可量化）

- 2 周内：完成“会议创建 -> 评审动作 -> 纪要导出”闭环。
- 4 周内：拿到首批付费用户（目标 5~20 个团队）。
- 8 周内：若试用转付费 > 8%，可继续加大投放和渠道合作；若 < 5%，需调整定位或卖点。

## 7. 风险与前置检查

- 版权与商用口径：仓库 `LICENSE` 为 MIT，但 README 含“仅学习研究”描述，建议尽快统一法律口径与对外声明。
- 成本风险：大模型调用成本要有配额与限流，否则毛利不可控。
- 身份与权限：会议动作涉及角色权限，需优先补齐强校验与审计日志。

## 8. 一句话结论

不建议继续做泛 AI 工具站；建议把当前系统收敛为“AI 评审会议室”，用“可追踪的决策闭环”作为核心卖点，最快 4 周可验证是否具备稳定变现潜力。
