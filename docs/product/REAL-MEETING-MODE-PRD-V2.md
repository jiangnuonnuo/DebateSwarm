# 真实会议化协作模式 PRD V2（甲方对接版）

## 0. 文档定位
- 产品负责人：`产品经理 - 001`
- 当前阶段：产品设计与规划，不进入代码实现。
- 目标：将当前“房间内辩论模式”升级为“接近真实小组会议”的协作系统。

## 1. 甲方需求对齐（原始诉求映射）
- 需求 1：把辩论模式升级为真实会议讨论能力。
- 需求 2：引入项目经理（仲裁者）主导会议节奏、汇报顺序、下一轮调度；老板可 `@` 指定人员汇报/执行。
- 需求 3：支持完整链路：老板提需求 -> 项目经理受理 -> 产品汇报/改稿 -> 架构评审/回退 -> 再改稿 -> 通过后执行。
- 需求 4：分版本迭代落地，避免单版本压力过大。
- 需求 5：所有不确定项必须与甲方确认，不由产品经理主观拍板。

## 2. 目标与非目标
## 2.1 目标
- 让会议具备“主持、汇报、质询、退回、再汇报、通过、分配执行”的闭环。
- 建立明确的角色权限和调度规则，避免多人并发时混乱。
- 输出可追踪的会议纪要、问题单、行动项和下一轮计划。

## 2.2 非目标
- 本阶段不承诺一次性实现自动编码执行全链路。
- 本阶段不替代已有研发流程工具（如 Jira、禅道）；优先打通本系统内闭环。

## 3. 角色模型（会议内）
- 老板（甲方）：提出需求、设置优先级、`@` 指定汇报/执行对象、做最终业务裁决。
- 项目经理（仲裁者）：主持流程、控制轮次、发起复议、决定是否进入下一角色或下一轮。
- 产品：产出需求设计、交互说明、验收标准；接收回退并修订。
- 架构师：评估可实现性、识别技术风险、提出约束与替代方案。
- 研发/测试：接收执行任务、反馈实现/验证状态与阻塞。

## 4. 会议机制设计
## 4.1 会议阶段状态机
- `待开始`：议题、角色、目标、时限已配置。
- `进行中`：按主持调度逐角色汇报与质询。
- `退回修改`：当前产出不满足通过条件，退回指定角色。
- `待决策`：关键分歧提交老板或项目经理裁决。
- `已结论`：形成阶段结论与行动项。
- `下一轮待开`：明确下一轮汇报人、目标与输入材料。

## 4.2 调度规则
- 默认调度权在项目经理。
- 老板可随时 `@角色` 或 `@具体人员` 插队提问、要求汇报或指定执行。
- 项目经理需在每次阶段结束给出：
  - 当前结论
  - 待修改问题列表
  - 下一汇报者
  - 下一轮会议触发条件

## 4.3 通过/退回判定
- 通过条件：目标完整、风险明确、可执行、责任人清晰。
- 退回条件：信息缺失、逻辑冲突、不可实现、验收不清。
- 每次退回必须记录“问题点 + 修改要求 + 截止时间 + 回报对象”。

## 5. 核心功能清单
## 5.1 会议控制台
- 创建会议（议题、目标、角色、优先级、时限）。
- 实时显示当前发言者、当前轮次、当前待决问题。
- 一键执行动作：通过、退回、补充提问、指派执行、结束会议、安排下一轮。

## 5.2 `@` 指令与指派
- 老板/项目经理支持 `@` 指定汇报对象。
- 支持 `@对象 + 动作 + 截止` 的结构化指派。
- 被指派对象进入“待执行队列”，状态可跟踪。

## 5.3 回退与复议链路
- 项目经理可将产品稿退回给产品。
- 架构师可将不可实现项退回给产品并附原因。
- 退回后自动生成“修订任务卡”，修订后回到原评审节点继续。

## 5.4 会议产出物
- 会议纪要（结论、争议点、未决项）。
- 问题清单（提出人、责任人、截止、状态）。
- 行动项清单（执行人、优先级、验收标准）。
- 下一轮计划（汇报者、主题、开始条件、预期输出）。

## 6. 关键业务流程（通用链路，议题可替换）
1. 老板提出业务需求（示例仅用于说明流程，不限定为登录功能）。
2. 项目经理创建会议并受理需求，指定产品先汇报。
3. 产品提交《需求设计方案》。
4. 项目经理评审，发现问题，退回产品并给修订要求。
5. 产品修订后再次提交。
6. 项目经理调度架构师评审可实现性。
7. 架构师若判定不可实现，提出问题并退回产品。
8. 产品按架构反馈修订后再次提交。
9. 架构师评审通过，项目经理确认进入执行分配。
10. 项目经理安排下一轮会议，指定下一汇报者与时间点。

## 7. 分版本落地规划（减压迭代）
## 7.1 V1（会议骨架版）
- 目标：先跑通“老板提需求 -> 项目经理主持 -> 产品/架构汇报 -> 结论输出”。
- 范围：
  - 会议创建与角色配置
  - 主持调度与轮次切换
  - `@` 指定汇报
  - 会议纪要与下一轮汇报者记录
- 暂不包含：复杂并发调度、自动任务执行编排。

## 7.2 V2（回退闭环版）
- 目标：跑通“退回修改 -> 重提评审 -> 通过/再退回”的闭环。
- 范围：
  - 退回原因结构化
  - 修订任务卡自动生成
  - 回到原评审节点继续
- 验收重点：每次退回必须可追踪、可复盘。

## 7.3 V3（执行调度版）
- 目标：把会议结论变成待执行任务并跟踪进度。
- 范围：
  - 执行任务池
  - 老板 `@` 指派执行
  - 汇报与执行状态看板
- 验收重点：老板能看到“谁在做、做到哪、何时汇报”。

## 7.4 V4（治理增强版）
- 目标：提升组织可控性与复用效率。
- 范围：
  - 模板化会议流程
  - 审计日志与关键操作留痕
  - 复盘报告与流程优化建议

## 8. 甲方已确认规则（2026-04-21）
- 老板拥有最高权限，可强制结束当前议题并决定是否开启下一轮。
- 老板与项目经理冲突时，最终裁决归老板。
- 允许老板越过项目经理直接下达指令；但流程上应优先经过项目经理协调。
- 会议无固定时长限制；必须支持手动终止；默认由项目经理判断会议是否结束。
- 超时处理本期不纳入产品规则，暂不做强约束。
- 最终结果必须由项目经理形成汇总并向老板汇报。
- 下一轮会议由老板发现问题后主动发起。
- “登录功能”仅是流程示例，不是当前版本开发目标。

## 9. V1 冻结范围（可进入架构评审）
- 会议创建与角色入会（老板、项目经理、产品、架构、执行角色）。
- 会议过程调度（项目经理主导，老板可随时 `@` 指派）。
- 评审动作闭环（通过、退回、补充、结束会议）。
- 会议结论汇总（由项目经理输出给老板）。
- 下一轮机制（由老板发现问题后手动发起新一轮会议）。
- 手动终止机制（会议任意阶段可被终止）。
