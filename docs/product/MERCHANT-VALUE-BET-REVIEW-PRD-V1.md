# 商家价值对赌评审系统 PRD V1（P0 冻结版）

## 0. 一句话定义
- 让两个方案在同一房间里完成“陈述-质询-裁决-试点-复盘”的闭环决策系统。

## 1. 产品定位
- 面向老板/业务负责人/项目经理的“方案对赌决策系统”。
- 核心价值不是“讨论热闹”，而是“商家价值可验证、可裁决、可复盘”。
- 本文档仅定义产品功能与规则，不涉及代码实现细节。

## 2. P0 必做功能（先做就有价值）

## 2.1 对赌立项卡
- 目标：把 A/B 方案从一开始放进同一评估框架，避免口头争论无结论。
- 必填字段：
  - A 方案名称与负责人
  - B 方案名称与负责人
  - 目标指标（如 GMV、转化率、留存）
  - 成本上限（预算、人天、调用成本）
  - 风险红线（不可触碰项）
  - 判胜条件（谁在什么条件下获胜）

## 2.2 证据强约束
- 目标：禁止“空观点”，每个方案必须交可审查证据。
- 每个方案提交时必须包含：
  - 数据依据
  - 用户影响
  - 实现成本
  - 失败预案
- 缺任一项不可进入裁决阶段。

## 2.3 交叉质询回合
- 目标：让 A/B 在同等规则下互相拆解风险，提升决策质量。
- 回合规则：
  - 方案 A 质询方案 B
  - 方案 B 反质询方案 A
  - 每轮质询必须绑定问题点与证据引用
  - 回答未闭环可要求补证后再答

## 2.4 仲裁动作台
- 目标：项目经理可执行标准化裁决动作，避免会议失控。
- P0 动作：
  - 通过
  - 退回补证
  - 进入试点
  - 终止
- 每个动作必须写明原因与下一责任人。

## 2.5 决策单自动生成
- 目标：会后直接可执行，避免“开完会没人跟进”。
- 自动生成字段：
  - 裁决结论
  - 责任人
  - 截止时间
  - 验收指标

## 2.6 试点跟踪与自动复盘
- 目标：裁决后进入小流量试点，用结果验证而不是凭感觉。
- P0 要求：
  - 试点里程碑设置
  - 里程碑结果回收
  - 自动复盘输出（目标达成、偏差原因、下一动作建议）

## 3. 角色与权限（P0）
- 老板：发起需求、设定业务目标、查看决策结论、决定是否重开下一轮。
- 项目经理：主持对赌流程、执行仲裁动作、产出最终汇总。
- 方案负责人 A/B：提交方案与证据、参与交叉质询、响应补证要求。
- 执行负责人：接收试点任务并回传里程碑结果。

## 4. P0 核心流程（闭环）
1. 老板发起“商家价值对赌”议题。
2. 项目经理创建对赌立项卡（A/B、指标、成本、红线、判胜条件）。
3. A/B 方案负责人提交证据包（四要素强约束）。
4. 进入交叉质询回合（A 问 B，B 问 A）。
5. 项目经理在仲裁动作台做决策（通过/退回补证/进入试点/终止）。
6. 系统自动生成决策单并分配责任人。
7. 若进入试点，按里程碑回收结果并自动生成复盘。
8. 老板根据复盘决定是否开启下一轮对赌。

## 5. P0 验收标准
- 对赌立项卡缺少任一必填项时不可提交。
- 证据四要素不完整时不可进入裁决。
- 系统可完整记录 A 质询 B、B 反质询 A 的回合历史。
- 仲裁动作必须留痕：动作、原因、责任人、时间。
- 每次裁决后自动生成决策单。
- 试点阶段可配置里程碑并沉淀自动复盘结果。

## 6. 非目标（当前不做）
- 不做复杂自动超时治理策略。
- 不做高级多方案并行编排（超出 A/B 对赌范围）。
- 不做自动代码实现能力。

## 7. 版本路线（减压迭代）
- V1（P0）：只做 A/B 对赌闭环与决策落地。
- V1.1：增强试点看板与复盘对比视图。
- V1.2：支持模板化对赌场景（增长、履约、营销等）。
