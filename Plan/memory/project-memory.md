# Project Memory

## Durable Decisions
- 2026-04-25: 小红书智能发布作为独立功能域建设，但入口集成在 Work 对话页面。
- 2026-04-25: 双模式并存：
  - A 模式：文案后审核 + 发布前审核；
  - B 模式：全自动，不设人工审核节点。
- 2026-04-25: B 模式失败策略为「自动重生成内容 + 重发布（允许参数变化）」，并启用三重上限（次数/耗时/成本）。
- 2026-04-25: 多 Agent 流程节点固定为：选题/策划 -> 文案 -> 生图(条件) -> 参数组装 -> 发布。
- 2026-04-25: A 模式在“文案后审核”节点决定是否补图；B 模式自动补图。
- 2026-04-25: 发布成功必须返回并展示可点击帖子链接（postUrl）。
- 2026-04-25: 发布节点按需注入指定 MCP（`http://127.0.0.1:18060/mcp`）；非发布节点不注入发布 MCP。
- 2026-04-25: 知识库检索优先级为“个人库优先，再补共享库”；共享库仅管理员可写。
- 2026-04-25: 个人知识库写入策略为“手动上传 + 发布成功自动沉淀”。
- 2026-04-25: 任务上下文采用“窗口内存 + 每轮 JSON 快照”；成功即删，失败保留 24h 后自动删。
- 2026-04-25: 校验采用“双层机制”：
  - 校验智能体负责语义与平台适配校验；
  - 发布前规则网关负责硬约束兜底。
- 2026-04-25: 图片二进制不入库，V1 素材先落本地临时存储，数据库仅保存素材引用与元数据。
- 2026-04-25: 定时发布在 V1 中按“任务受理成功并落库”定义成功，后续由用户手动确认最终帖子是否可见。
- 2026-04-25: V1 先跑通单用户默认账号，数据模型预留多账号绑定与任务选账号能力。
- 2026-04-25: 发布失败重试需要按错误类型区分处理，不能统一重试。
- 2026-04-25: 发布域核心表按任务、尝试、审核、模板、账号、素材、知识、快照拆分设计。
- 2026-04-26: 团队协作主文档统一沉淀在 `Plan/versions/v1/`，`backend/docs/` 仅保留技术实现镜像。
- 2026-04-26: 任务流转统一按状态机事件表实现，禁止 Controller/Repository 直接写死 `task_status/current_stage/attempt_status`。

## Open Risks
- 测试期图片走内存存储，服务重启素材丢失风险已知且暂可接受。
- B 模式允许全量参数变化，可能带来内容漂移，需要后续策略收敛。
- 智能择时尚未纳入 V1，B 模式默认直发可能影响发布时间质量。
- 定时发布在 V1 中不做自动复核，可能出现“任务已受理但帖子状态需人工再查”的运营成本。

## Stable Constraints
- 当前阶段仅固化 V1 第一版基线，后续允许在同一版本文档内修订。
- 不将图片二进制写入数据库；仅保留引用与元数据。
- 先规划后实施，接口与数据库变更需后续逐项确认。
